# Camera Language · 運鏡導演體系

> **何時讀本檔案**：畫面裡出現任何「鏡頭級」運動之前——zoom / pan / orbit / parallax /
> 轉場 / 定場謝幕，只要動的是「鏡頭」而不是「元素」，先讀這裡再寫 timeline。
> 元素怎麼動（入場/stagger/物理感）歸 `animation-best-practices.md`；

> 參數出處標註約定：**(HuaRec)** = 花錄 Studio 運鏡導演系統實測參數；

## §0 · 立論 · 運鏡是預算制，不是特效導向

大多數 AI 生成動畫的運鏡是「特效導向」思維：哪裡能加 zoom 就加 zoom，鏡頭動得越多越「高階」。
這是暈和廉價感的共同來源。正確的心智模型來自兩條公理 (HuaRec)：

- **A1 可見性不變數**：任意時刻，觀眾該看的東西必須在可視區內（含 8% 安全邊距）。
  違反的鏡頭寧可降倍率、並鏡或不拍。
- **A2 舒適預算**：每次鏡頭變化都是一筆注意力消費，必須預算化管理。
  預算花完了，再好的鏡頭也不拍。

| 預算項 | 典型值 | 調節手感 |
|---|---|---|
| 相鄰鏡頭變化間隔 | ≥2.6-3.0s（克制檔 5.0s） | 低於 2.6s 觀眾開始暈；MTV 式快剪不適用於產品演示 (HuaRec) |
| 任意 15s 視窗內鏡頭變化 | ≤4-5 次（克制檔 3 次） | 超了就砍最弱動機的那一鏡，不是壓縮間隔 (HuaRec) |
| 推進倍率下限 | 1.25x | 低於 1.25x 的 zoom 視覺變化感知不足，純屬晃動，不拍（定場 1.06x 是唯一例外）(HuaRec) |
| 推進倍率上限 | 2.3x（克制檔 1.8x） | 再高畫素密度撐不住，先換素材再談倍率 (HuaRec) |
| 每分鐘鏡頭數 | 克制 ≤4 鏡/分，常規 ≤6 鏡/分 | 「留呼吸，不是 MTV」(HuaRec) |

再疊兩條風格公理 (shotcraft)：

1. **電影感 = 運鏡 × 光影 × 節奏 × 聲音，不等於炫技動畫**。四個維度各自及格，勝過一個維度做到極致。
2. **節奏偏好單向：寧慢勿快**。歷史使用者回饋全部指向「放慢/停留」，沒有一條指向「加快」。
   拿不準時長時，選長的那個；拿不準要不要動鏡時，選不動。

這兩條與 best-practices §0.2 的「禮讓觀眾」同源：鏡頭是替觀眾的眼睛做決定，
決定做得越少、越準，觀眾越信任你。

## §1 · 鏡頭語言詞彙表 · 運鏡動機決策表

每個鏡頭動作先問動機：**這一鏡替觀眾回答了什麼問題？** 答不上來就不動。

| 鏡頭 | 動機（什麼時候給） | 參數區間 | 禁忌 |
|---|---|---|---|
| **push in 推近** | 「接下來看這裡」：聚焦一個具體 UI 元素 / 資料 / 關鍵詞；緊張度爬升 | 倍率 1.3 / 1.45 / 1.8 / 2.3 檔（見 §4）；時長走對數公式；提前 0.15s 進鏡 (HuaRec) | <1.25x 不推；滾動 / 切頁 / 播影片等全螢幕級變化期間不推（「滾動時推近會暈」）；旁白中段不動鏡（見 §6 move on pause）(HuaRec) |
| **pull out 拉遠** | 揭示全貌與上下文：「原來它屬於一個更大的系統」；收尾謝幕 | 時長同對數公式；謝幕拉出 0.55s + ≥0.8s 全景停頓 (HuaRec) | 禁「出-進-出」泵動：鏡間空隙小於過渡時長時直接接下一鏡，不回 1x（見 §5）(HuaRec) |
| **pan 平移** | 兩個中距焦點之間轉移（歸一化距離 0.22-0.45）；一鏡掃過多個並列元素 | 聯合倍率 ≥1.25 才值得平移；斜向 pan 用雙頻正弦（X/Y 頻率比 0.22:0.35，振幅 30-40px）(HuaRec / 本 skill 既有) | 焦點距離 >0.45 不平移（對角橫跳），棄鏡；純單軸 pan 有機械感，優先斜向 |
| **orbit 環繞** | 單主角質感特寫，「實體感」最強的一鏡；hero 元素立傳 | rotY 主導 + persp 1100-1200px；實測機位 rotX46/rotY−30/rotZ9 → rotX42/rotY26/rotZ−7 (shotcraft) | 一種手法全片只當一次主角 (shotcraft)；資訊密集畫面停用（機位服務可讀性，文字多就正視） |
| **dolly zoom** | 「世界觀反轉」的揭示瞬間：主體不變、語境劇變 | 偽配方見 §8：主體釘死，背景 scale 1→2.0-2.5 + opacity ≤0.6 (shotcraft) | 全片最多一次；無敘事落差時用它 = 純炫技 |
| **靜止** | 文字閱讀、真人速度互動演示、資訊密集鏡頭；預算不足時的預設答案 | 品牌字標落定 hold ≥1s；批次動效收尾 0.5s 靜止；開場主體動作弧 ≥3s (shotcraft) | 無。靜止不動永遠是合法選擇，「不給鏡頭」本身就是導演決定 |

兩條橫向規則：

- **速度感來自加速度，不是勻速快** (shotcraft)。勻速運動讀作廉價 PPT；
  想要「快」的感覺，用短促的加速段 + 長緩衝，不是把整段 duration 砍半。
- **機位服務可讀性** (shotcraft)：資訊密集鏡頭正視；文字特寫用側向水平機位
  （rotY 主導、rotX 很小）；禁全域性一刀切傾斜；產品宣傳片預設不加手持抖動。

## §2 · zoom vs dolly 選型 · 3D 真假裁決

「推近」有兩種實作，觀感完全不同，先選型再寫程式碼：

| 維度 | zoom（scale 縮放） | dolly（perspective + translateZ 前移） |
|---|---|---|
| 視差 | 無。所有層等比放大，畫面是「一張圖被放大」 | 有。近層快、遠層慢，畫面是「鏡頭在空間裡前進」 |
| 觀感 | 乾淨、資訊型，適合 UI 特寫 / 資料聚焦 | 空間感、電影感，適合 hero 展示 / 氛圍段落 |
| 成本 | 低：單個 transform | 高：需要分層結構 + preserve-3d，且有柵格化發糊問題（§3.4） |
| 選型規則 | 內容是平面資訊（介面、文件、圖表）→ zoom | 內容有明確的「前景/主體/背景」層次，且這層次值得被看見 → dolly |

**3D 真假裁決**（化解本 skill 兩處舊文矛盾的邊界線）：

- 參與 3D 的元素 **≤8 個** → 用真 translateZ 分層（best-practices §4.7 的黃金角配方照用）
- 元素 **≥20 個** → 放棄真 3D，用 shadow / blur / 明度差做假深度（hero-case-study 的立場）
- 8-20 之間 → 問一個問題：這段鏡頭需要視差嗎？需要才上真 3D，不需要就假深度。
  真 3D 的成本不在寫，在調：每加一層就多一組「透視失真 + 文字發糊 + 層級穿插」要排查。

## §3 · Camera Rig 實作約定

鏡頭運動和元素動畫**不許搶同一個 transform**。所有鏡頭級運動收口到一個專職容器上。

### 3.1 分層容器結構

```html
<div id="viewport">          <!-- 固定可視區，overflow: hidden，持有 perspective -->
  <div id="camera">          <!-- 鏡頭層：只承載相機 transform，別的什麼都不幹 -->
    <div id="world">         <!-- 世界層：所有畫面內容住這裡，元素動畫只動 world 內部 -->
      ...場景內容...
    </div>
  </div>
  <div id="hud">             <!-- 字幕 / 角標 / chrome：與 #camera 平級，天然不跟鏡頭動 -->
  </div>
</div>
```

分工鐵律：

- `#camera` 上只出現鏡頭 tween（translate / scale / rotate / zoom 屬性），元素入場、stagger、
  hover 態一律寫在 `#world` 內部的元素上。兩層互不知曉，鏡頭隨時可以整體重排而不碰元素動畫
- 字幕和 chrome **首選放 `#hud`**，零成本保持靜止；只有「必須跟著 world 裡某元素走、
  但字號要恆定」的標註（如跟隨 tooltip），才在該元素上做 counter-transform：
  `scale(1/zoom)` 反向抵消鏡頭縮放，每幀與相機同步更新
- **transform-origin 就是推進目標點**：平面 zoom 把 origin 設到目標元素中心再 scale，
  等價於「鏡頭對準它推近」。PageCam 模式下由 cx/cy 承擔同一職責

### 3.2 PageCam 關鍵幀模型（shotcraft，2.5D 相機數學）

把鏡頭狀態定義成關鍵幀物件，鏡頭運動 = 關鍵幀之間插值：

```
{ frame, cx, cy, zoom, rotX, rotY, rotZ, persp }
```

cx/cy 是**世界座標系裡鏡頭對準的點**，zoom 是倍率。以 1920×1080 畫布為例
（其他尺寸把 960/540 換成 W/2、H/2）：

**平面模式**（無旋轉，純 zoom + pan）：

```
transform: translate(960 − cx·zoom, 540 − cy·zoom) scale(zoom)
transform-origin: 0 0
```

**3D 模式**（有 rotX/rotY/rotZ）：

```
外層（#camera）: perspective: persp·zoom;  perspective-origin: 960px 540px
內層（#world）:  zoom: {zoom};                        /* 注意是 CSS zoom 屬性，見 §3.4 */
                Tx = 960/zoom − cx;  Ty = 540/zoom − cy
                transform: translate(Tx, Ty) rotateY() rotateX() rotateZ()
                transform-origin: cx cy
                transform-style: preserve-3d
```

典型機位參數 (shotcraft 實測)：全頁 zoom 0.78 → 特寫 2.6；
側拍 rotY34 / rotX8 / persp1200（側拍優於俯拍，rotY 主導 + rotX 只給一點）；
orbit 起止機位見 §1 表。

### 3.3 rig 施工注意（鏡頭專屬坑）

- **pan 露邊**：`#world` 必須比可視區大（四周外擴 bleed ≥ 最大 pan 振幅 + 8% 邊距），
  否則平移時露出畫布外的空白。這是 A1 可見性公理的反面：不該看的也不能看見
- **perspective 被打斷**：`#camera` 與 `#world` 之間的任何中間層加了
  `overflow: hidden`、`filter`、`opacity <1` 都會建立新 stacking context，
  殺掉 preserve-3d，3D 分層瞬間變平。3D 模式下濾鏡效果只加在最內層元素上
- **逐幀越界備援** (HuaRec)：鏡頭焦點跟隨動點時，每幀檢查目標是否越出可視區，
  越出則保持倍率、只沿越界軸做最小修正拉回邊界。寧可鏡頭「讓一步」，不許目標出畫

### 3.4 CSS zoom 柵格化技法 · 根治 3D 文字發糊（全庫最貴知識，shotcraft）

**問題**：3D 模式下用 `transform: scale()` 放大頁面，Chromium 按元素的佈局尺寸柵格化，
再把點陣圖放大，文字必糊。倍率越高糊得越狠，2x 以上不可交付。

**解法**：放大不走 `transform: scale`，走 **CSS `zoom` 屬性**。`zoom` 是佈局級縮放，
Chromium 按放大後的尺寸重新 layout 並柵格化，文字在任意倍率下保持向量級銳利。
§3.2 的 3D 模式公式裡內層寫 `zoom: {zoom}` 而不是 `scale({zoom})`，正是為此。

配套要點：

| 要點 | 做法 | 出處 |
|---|---|---|
| 座標補償 | `zoom` 改變佈局座標系，translate 量要除以 zoom：`Tx = 960/zoom − cx`（§3.2 公式已含） | (shotcraft) |
| 與 reflow 禁令的關係 | gsap-recipes §6.2 禁 tween 佈局屬性是因為整數 snap 抖動；`zoom` 是整頁級縮放，snap 量不可感，且文字銳利收益遠大於。**此技法是 §6.2 的唯一合法例外，只用於 `#world` 相機層** | (實測) |
| 渲染環境 | HyperFrames / Playwright 離線逐幀 seek 渲染下完全適用：每幀重 layout 的耗時不影響產物，只影響渲染時長。即時瀏覽器 preview 可能掉幀，屬正常，以渲染產物為準 | (shotcraft) |
| 點陣圖素材增強 | 全頁截圖用 2x 取樣；特寫元素另備 4x 單獨截圖，在推進期用 6f 交叉淡入蓋住低倍紋理 | (shotcraft) |
| 景深氛圍 | DoF 只做氛圍：頂部漸變帶 blur + mask，不做逐層真實景深 | (shotcraft) |

## §4 · 鏡頭緩動與時長

### 4.1 緩動詞彙

| 場景 | easing | 調節手感 |
|---|---|---|
| 主動運鏡（推近/拉遠，有明確起止點） | `cubic-bezier(0.65,0,0.35,1)` = GSAP `power3.inOut` | 兩端都穩，「導演給鏡頭」的感覺；**絕不線性、絕不彈簧過沖** (HuaRec) |
| 跟隨式運鏡（鏡頭追一個已開始的動作） | `cubic-bezier(0.33,0,0.15,1)` | 出發輕快、剎車極長，鏡頭像「跟上去」而不是「切過去」；shotcraft 相機預設 |
| 持續漂移（idle drift、勻速巡覽） | `sine.inOut` yoyo 或 `none` | 唯一允許相機勻速的場景（gsap-recipes §1 既有規則）；有起止點的動作停用 |
| 游標/焦點跟隨平滑 | `quickTo` + ~0.15s 平滑；路徑插值 Catmull-Rom | 前向+後向 EMA 的零相位思路：跟得緊但不抖 (HuaRec) |

兩套預設衝突時的裁決：單次推拉信 HuaRec（power3.inOut），複合移動、
多段連續鏡頭信 shotcraft（0.33,0,0.15,1）。

### 4.2 zoom 時長對數公式（固定 duration 是業餘感的來源）

所有推拉時長由倍率變化量決定，保證任何幅度的 zoom「視覺速度」一致：

```
duration = 0.55 × |ln(zoom₂ / zoom₁)| / ln 2      clamp 到 [0.30, 0.94] 秒
```

1→2x 推近正好 0.55s；1→1.3x 約 0.30s（觸底）；0.78→2.6x 觸頂 0.94s。(HuaRec)
大景別過渡更久、小景別更短，防「一躥到位」也防「拖沓」。

### 4.3 zoom 檔位表

| 檔位 | 倍率 | 用途 | 調節手感 |
|---|---|---|---|
| 定場微推 | 1.06x | 僅用於開場定場（§6），觀眾感知不到 zoom、只感知到「畫面活著」 | 唯一允許低於 1.25x 的檔位 (HuaRec) |
| 輕推 | 1.3x | 提示性聚焦：不打斷全域性閱讀，只是「注意這一片」 | |
| 中推 | 1.45x | 標準 UI 特寫：一個面板 / 一段程式碼 | |
| 重推 | 1.8x | 單元素特寫：一個按鈕 / 一個數字 | 克制檔的上限 (HuaRec) |
| 上限 | 2.3x | 極限特寫，素材必須扛得住（2x 截圖 / 4x 切片，§3.4） | 超過就換素材，不硬推 (HuaRec) |

定景公式 (HuaRec)：`scale = 0.8 / max(目標包圍盒歸一化寬, 高)`，再夾到檔位區間。
內容佔可視區 80%，留 20% 呼吸，不頂格。

### 4.4 節奏預算（與 §0 預算表聯動）

- 相鄰鏡頭變化間隔 ≥2.6-3.0s；15s 視窗 ≤4-5 次 (HuaRec)
- 動作前 0.15s 進鏡（鏡頭先到，動作後發生），動作結束後停留 1.2s 再走 (HuaRec)
- 時長 <1.2s 的孤立小動作不值得單獨給鏡頭，防「點一下泵一下」(HuaRec)

## §5 · 鏡間語法 · 防暈核心

**暈不是單個鏡頭造成的，是鏡頭之間的接法造成的。** 「出-進-出」泵動和遠焦點連續橫跳
貢獻了絕大多數眩暈感 (HuaRec)。對相鄰兩鏡（間隔 <1.5s），按焦點距離三分：

| 焦點歸一化距離 | 接法 | 說明 |
|---|---|---|
| <0.22（近） | **並鏡** | 合併為一鏡：取兩目標的聯合包圍盒重算倍率，一鏡看完 |
| 0.22-0.45（中） | **改平移** | 寧可倍率廣一點（聯合倍率 ≥1.25），一鏡平移過去，不做「出再進」 |
| >0.45（遠/對角） | **棄鏡** | 砍掉動機更弱的那一鏡。**絕不連拍兩個遠焦點**，對角橫跳是最暈的一種接法 |

補兩條時序規則 (HuaRec)：

- **間隙短則直接銜接**：相鄰鏡頭空隙小於過渡時長時，不回 1.0x，直接從目前倍率過渡到
  下一鏡的倍率和焦點。回 1x 再推是「泵動感」的直接來源
- **間隙 ≥1.5s 才允許「拉出再推進」**：觀眾有足夠時間在全景裡重新定位，出-進才不暈

## §6 · 電影開閉幕 · 定場、謝幕、move on pause

三條語法成本極低，作品感提升明顯 (HuaRec)：

1. **定場（establishing shot）**：片長 >14s 且首個正式鏡頭在 7s 之後時，
   開場插入 [0, 3.0s] 的 **1.06x 中心微推**：開機即處於輕推近態，3 秒內緩出落回全景。
   觀眾的第一感受是「鏡頭是活的」，而不是「PPT 開始播放了」
2. **全景謝幕鐵律**：末鏡提前收口，留出 0.55s 拉出過渡 + **≥0.8s 全景停頓**。
   成片永遠以全景靜止收尾，**絕不在推近態戛然而止**。與 best-practices「戛然而止 + hold」
   收尾完全相容：hold 的那一幀必須是全景
3. **Move on pause**：cut on action, move on pause。有旁白的動畫裡，鏡頭移動如果撞在
   說話中段，向早處吸附到最近的語音靜默點（最多前移 0.8s，**只提前不推後**）。
   觀眾在聽覺空檔移動視線的認知成本最低。解說 pipeline（voiceover-pipeline.md）排鏡頭時
   直接拿 narration 的分句間隙當吸附點

## §7 · 轉場語法表 · 三層詞彙

轉場是獨立層：接縫按**能量落差**選型，一個接縫只用一式，轉場幀從相鄰鏡頭預算裡撥出。
「公認優秀的釋出片全程沒有一次裸切」(shotcraft)。

### 7.1 shot-transitions 六式（有存在感的轉場，用於能量落差大的接縫）

| 式 | 適用能量落差 | 參數 | 坑 |
|---|---|---|---|
| 流白 flash-wash | 高→高，段落強轉 | 白場 2-4f 峰值，兩側各 5f 漸變 | 白閃只蓋切點，不當裝飾反覆用 |
| 穿暗場 dip-to-dark | 高→低，情緒降檔 | 壓暗到 rgba(20,20,20,0.9) 量級，總長 ≤0.6s | 暗場裡別停留，觀眾以為片子結束 |
| 虛焦接力 defocus-handoff | 中→中，平級話題切換 | 出鏡 blur 0→8px 與入鏡 blur 8px→0 交疊 ≥8f | blur 大面積 ≤24px（DoF 效能約束） |
| 黑場字卡 title-card | 章節級分隔 | 字卡 hold ≥1s，前後各 0.3s 過渡 | 全片 ≤2 張，多了像幻燈片 |
| whip-pan 甩鏡 | 低→高，能量急升 | 兩端 hold ≥20f → 8f 甩 1.5 個畫面寬，峰值 ≥300px/f 才糊得透 (shotcraft) | 慢了就是普通 pan，糊不透反而露拙 |
| mask-wipe 穿窗 | 空間轉移，「穿過一個介面進入另一個」 | 遮罩緣 easing `(0.4,0,0.6,1)` (shotcraft) | 遮罩形狀必須來自畫面內已有元素（視窗/卡片圓角），憑空的形狀是 slop |

### 7.2 hidden-cut 三式（觀眾察覺不到切過的轉場）

| 式 | 做法 | 出處 |
|---|---|---|
| flash-cut 白閃跨切 | 白閃跨騎硬切點，兩側各 5f，只蓋切點 | (shotcraft，實證參數) |
| 前景遮擋切 | 一個前景元素（卡片/面板/游標手）掃過全螢幕的瞬間換景 | (推測：通用電影語彙，參數待實測) |
| 運動糊切 | 高速運動峰值幀上硬切，兩側運動方向一致，motion blur 吞掉切點 | (推測：通用電影語彙，參數待實測) |

### 7.3 travel 兩式（空間連續的轉場，能量不落差、場景在移動）

| 式 | 做法 | 坑 |
|---|---|---|
| 共享元素歸位 | 前鏡的某元素（logo/卡片）連續運動到後鏡中它的新位置，FLIP 思路的鏡頭版 | 元素在兩鏡中必須同一身分，形變過大就斷了「同一個東西」的認知 |
| 字腔穿越 | 鏡頭推進穿過大字的字腔（O/口/0 的空洞）進入下一場景 | 字腔尺寸要夠（≥1/3 螢幕高度），穿越段 zoom 走對數時長上限 0.94s |

選型速查：能量落差大 → 六式挑一；不想被察覺 → hidden-cut；兩個場景空間上連續 → travel。
硬切不是停用，是「必須被上述任意一層包裝過」。

## §8 · 多層 parallax 配方 · 偽 dolly-zoom

### 8.1 parallax 層速度係數 (shotcraft)

| 參數 | 典型值 | 調節手感 |
|---|---|---|
| 層速度係數 | 遠景 0.35 / 中景 0.7 / 近景 1.4（相機位移的倍數） | 相鄰層速比 **≥2 倍**才可辨，1.2 倍的差異觀眾讀不出來 |
| 層數 | ≤4 層 | 超過 4 層的視差沒人看得出來，純浪費預算 |
| 實作 | 各層根據同一個相機 x/y 乘各自係數 translate | 全部由相機狀態推導，seek-safe；別給每層獨立 tween |

### 8.2 偽 dolly-zoom（純 CSS，無需真 3D）

```
主體：釘死不動（或只做 ≤1.02x 的呼吸）
背景：scale 1 → 2.0-2.5，同時 opacity 降到 ≤0.6
```

主體不變、背景湧向觀眾，產生「世界在逼近而主角凝固」的反轉感 (shotcraft)。
時長給足（≥1.2s），用途見 §1：全片最多一次，留給真正的揭示瞬間。

## §9 · 運動派生訊號 · blur / 跟隨 / 餘震

鏡頭的「速度感」不靠更快的 duration，靠從速度**派生**出來的次級訊號 (shotcraft / HuaRec)：

| 訊號 | 公式 | 參數 |
|---|---|---|
| 速度驅動 blur | `v = velocityAt(f)`（中央差分：`(pos(f+1)−pos(f−1))/2`），blur 強度 ∝ v | zoom 速度 >0.6/s 才觸發，強度 `min(10, v×5)`px。**只在動的瞬間有模糊，靜止幀永遠銳利** (HuaRec) |
| lagged 跟隨層 | 跟隨層 = 主體在 `f − delay` 處取樣 | 陰影滯後 2f、殘影滯後 4f (shotcraft)。殘影可取代 motion blur：5% 路徑滯後 + blur(6px) + opacity 0.25·(1−t) |
| dampedSettle 餘震 | `e^(−d·t) · sin(2π·f·t)`，f≈0.1、damping≈0.15 | 鏡頭急停後的 1-2 個微小殘擺，幅度 ≤3px；主動運鏡（§4.1 inOut 族）不加，只給 whip-pan / 急剎類 |

三者全部是時間的純函式（差分、延遲取樣、閉式衰減），天然 seek-safe，
符合 gsap-recipes §6 的確定性要求。

## §10 · 運鏡自檢清單（寫完 timeline 後 60 秒）

- [ ] 每個鏡頭動作都答得出「替觀眾回答了什麼問題」？答不出的刪了嗎？
- [ ] 沒有 <1.25x 的 zoom（定場 1.06x 除外）？
- [ ] 相鄰鏡頭間隔 ≥2.6s，15s 視窗 ≤4-5 次？
- [ ] 所有推拉時長走對數公式，沒有拍腦袋的固定 duration？
- [ ] 推拉 easing 是 power3.inOut，沒有 linear / 彈簧過沖？
- [ ] 相鄰鏡頭按焦點距離做過三分裁決（並鏡/平移/棄鏡）？沒有兩連遠焦點橫跳？
- [ ] 間隙短的鏡頭直接銜接，沒有回 1x 的泵動？
- [ ] 片長 >14s 且首鏡晚於 7s：加了 1.06x 定場微推？
- [ ] 結尾是全景靜止 ≥0.8s，不在推近態收尾？
- [ ] 有旁白：鏡頭移動吸附到了語音間隙（只提前 ≤0.8s）？
- [ ] 鏡頭運動全部收口在 `#camera` 層，沒和元素動畫搶 transform？
- [ ] 3D 文字特寫走了 CSS zoom 柵格化，沒有 scale 放大發糊？
- [ ] 每個轉場接縫只用一式，全片沒有裸切？
- [ ] parallax 相鄰層速比 ≥2 倍、≤4 層？
- [ ] blur 只出現在運動瞬態，靜止幀全部銳利？
