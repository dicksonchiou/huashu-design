# Storyboard Basics · 輕量分鏡與畫面構圖

> 任何動畫開工前的分鏡方法，不論 5 秒還是 50 秒。核心一句話：**每一鏡先是一張會動的封面**。
>
> 方法論來源：花叔配相簿 300+ 張封面實測提煉的定格幀規則（S1-S11）、video-shotcraft 106 張鏡頭卡的能量骨架判例、HuaRec Studio 運鏡導演系統的鏡頭預算公理。

---

## 0 · 定位：與 launch-film 導演稿的分工

本檔案是 `launch-film-director-notes.md` 的**日常輕量版**。launch film 萬字導演稿是重灌流程，日常動畫不需要那套，但**分鏡這道工序本身不能省**——省掉的結果是時間表思維（第幾秒出什麼元素），不是畫面思維（這一幀長什麼樣）。

| 片長 / 型別 | 分鏡要求 | 依據 |
|---|---|---|
| < 20s 動畫、motion graphic、demo | 本檔案的**輕量分鏡卡**（§5，每鏡一行） | 20s 以下不值得寫萬字，但每鏡的畫面構圖必須先想清楚 |
| ≥ 20s 動畫 | Gate 檔案協議要求的 `導演稿.md`，**最低要求 = 本檔案的分鏡卡格式**（§5 八欄位一個不能少），在此之上自由加厚 | SKILL.md「Gate 檔案協議」 |
| launch film / 品牌宣傳片 /「Apple 級」預期 | 在分鏡卡基線上升級為萬字 director's notes | `launch-film-director-notes.md`，它的 Part IV 每鏡 10 欄位是本檔案八欄位的重灌版 |

觸發邊界：使用者說「快速做個動畫」「簡單 demo」時不要甩出萬字流程，但**分鏡卡照畫**。分鏡卡的成本是十幾分鍾，跳過它的成本是整片重工（2026-07-17 B00 實測：跳過畫面設計直接寫程式碼，動效全綠、視覺被一票退回）。

與既有檔案的關係：

- `animation-best-practices.md` 管「怎麼動」（節奏、easing、運動語言），本檔案管「每一幀長什麼樣、鏡頭之間怎麼排」，兩者正交
- `cinematic-patterns.md` 的 Scene-based 敘事是本檔案的前提：先有 scene 劃分，才談每個 scene 的定格幀
- 運鏡的實作參數（camera rig、zoom 與 dolly 的區別、鏡頭緩動）→ `camera-language.md`，本檔案只在設計層引用它的詞彙

## 1 · 核心立論：每一鏡先是一張會動的封面

配相簿做了 300+ 張封面後沉澱出一個判斷：**一張好封面 = 1 個具象主角 + ≤3 個活躍元素 + 1 條清晰的視線引導**。動畫的每一鏡，先按這個標準設計成一張靜態封面，再讓它動起來。

**封面 = 分鏡定格**。檢驗方式極其具體：隨機暫停成片的任何一幀，這一幀應該能直接當封面用。過不了封面測試的幀，說明這一鏡的構圖沒設計，只是元素在時間軸上各自運動的疊加。

為什麼動畫反而更容易違反這條：動畫會用「元素是分時出現的」自我辯護，前一個還沒退場後一個已經入場，結果每一幀都擁擠。靜態封面沒有這個藉口，所以封面的紀律恰好是動畫最缺的紀律（配相簿實測核心啟發 #1）。

順序也因此定死：**先擺定格幀，再編排運動**。§6 的 thumbnail pass 就是這個順序的可執行版本。

## 2 · 定格幀十一律

配相簿 S1-S11 規則的動畫語境改寫。這是本檔案的心臟，每一鏡的構圖設計逐條過。

### 律一 · 封面測試（S1）

每個 scene 的定格幀必須有：**1 個具象主角 + ≤3 個活躍元素 + 1 個清晰視覺焦點**。

「≤3」是**每一幀的不變數**，不是每個 scene 的總量。新元素入場，舊元素必須退場（淡出、退到後景、blur+dim 都算退場），同一個畫面活躍元素預算恆定。寫時間軸時對每個時間點數一遍同一個畫面元素，超了就砍入場或提前退場。

> 自檢：隨手挑三個時間點暫停，數同一個畫面活躍元素，有沒有一幀超過 3？

### 律二 · zoom 終點必須是具象錨點（S2）

push-in / zoom 的終點只能是：品牌 logo、關鍵數字、UI 裡的那個按鈕、那行程式碼、人物表情。**背景紋理、氛圍元素、裝飾圖形不配 zoom**。推近一個沒有資訊的東西，等於告訴觀眾「這裡其實沒什麼可看的」。

HuaRec 判例補一刀：**倍率 < 1.25x 的 zoom 不值得做**（視覺變化感知不足，純屬晃動；唯一例外是開場 1.06x 定場微推）。設計分鏡時每個 [CAMERA] 推近動作都寫明錨點是什麼，寫不出錨點就刪掉這次運鏡。

> 自檢：這一鏡 push-in 的終點能用一個名詞說出來嗎（那個按鈕 / 那個數字 / 那個 logo）？說不出就刪運鏡。

### 律三 · 視線與箭頭 = 鏡頭運動指令碼（S3）

靜態封面裡「人物視線朝向主體物、一張圖只放一個箭頭」的規則，翻譯到動畫就是：**定格幀裡的引導線，就是這一鏡的鏡頭運動指令**。鏡頭跟著視線走、沿著箭頭推、順著 UI 的閱讀方向 pan。

一個 scene 只有 1 條引導線。定格幀裡找不到引導線，說明這一鏡根本不知道該怎麼動。此時不要硬編一個運鏡，回去修構圖（配相簿核心啟發 #3）。

> 自檢：把定格幀給人看 3 秒，他的視線路徑和你計劃的鏡頭運動一致嗎？

### 律四 · 字畫分工，兩條軌（S4 + 配相簿 C 系列）

文字軌和畫面軌是兩條獨立時間軸，分工不重疊：

| 規則 | 內容 | 出處 |
|---|---|---|
| 字扛鉤子 | 每鏡大字 2-6 字硬上限，主文案 2-4 字最佳；字說鉤子，畫面扛氛圍，不讓畫面硬演文字 | 配相簿 C1/C3 實測 |
| 兩拍入場 | 大字入場節奏固定兩拍：**動作詞先砸，定語色塊後補**（「實測」滿版砸下，「Claude 4.8」色塊隨後貼上） | 配相簿 C5 |
| 字落負空間 | 文字永遠落在構圖預留的負空間，不壓主角、不壓焦點 | 配相簿 C2 |
| 實心強色 | 花字必須實心強色；**空心白字 + 彩色描邊絕對停用** | 配相簿 G 禁區 |

> 自檢：遮掉畫面只留字，鉤子還在嗎；遮掉字只留畫面，構圖還成立嗎？兩問都過才算分工乾淨。

### 律五 · 百分比空間語言（S5）

分鏡卡裡的構圖描述必須寫到百分比粒度：「產品截圖右上 60% 帶透視、人物左下 25%、大字壓截圖頂部邊緣、距四邊 10% 安全區」。

這不是儀式感，是工程介面：**百分比語言直接對映 CSS/GSAP 佈局參數**，實作 agent 拿到就能翻譯，不需要再做構圖決策。寫「左邊放產品右邊放字」這種粒度等於沒寫（gbro 構圖模板對比實測：百分比粒度的 prompt 和模糊描述的產出差一個檔次）。

> 自檢：這一鏡的構圖描述裡有沒有至少 3 個百分比數字？沒有就還是文學描述，不是 spec。

### 律六 · 前中後景 = parallax 三層（S6）

定格幀設計時顯式寫出前景 / 中景 / 後景各是什麼、誰遮擋誰。這個分層就是天然的 parallax 素材：三層三個速度，遮擋關係的變化就是深度感的來源。

實作參數直接抄 shotcraft 判例：視差層速度係數 0.35 / 0.7 / 1.4，**層間速度比 ≥2 倍才可辨**，層數 ≤4。

> 自檢：說得出這一幀的前中後景各是什麼、誰遮擋誰嗎？說不出就還沒分層。

### 律七 · setup → payoff，開場幀擺懸念（S7）

每個 scene 的開場定格幀留一個缺口（未完成的橋、還沒揭曉的數字、半個螢幕空白），這一鏡的運動負責閉合它。「從 A 到 B」的結構天然就是轉場敘事：上一鏡的 payoff 可以直接是下一鏡的 setup。

反面是「開場幀已經把所有資訊擺全，然後元素原地做動效」：那是會動的海報，不是鏡頭。

> 自檢：這一鏡的開場幀和結束幀並排放，觀眾能說出「什麼被達成了」嗎？

### 律八 · 物化 + 過程感選意象（S8）

抽象概念必須物化成可見的實物動作，且**優先挑有過程感的動作**：「連線」= 橋一段段搭起來、「降價」= 價格牌 $89 逐字劃掉變 $29、「AI 味重」= 稿紙上 stagger 長滿整齊的灰方塊。

動作本身就是動畫指令碼：選對了意象，畫面焦點和鏡頭運動會從意象裡自己長出來，不需要另外發明動效。方法是先做費曼式翻譯（這個概念怎麼「發生」？），翻譯完再談畫風（配相簿核心啟發 #4）。

> 自檢：這個意象能用一個動詞概括嗎（搭、劃、長、落）？只能用名詞描述的意象沒有過程感，換一個。

### 律九 · 風格 × 構圖正交（S9）

配相簿最重要的架構認知，原樣遷移：**風格皮膚全片定一次**（色板、字型、材質、背景邏輯），**構圖模板逐 scene 換**（這一鏡居中特寫、下一鏡三列網格、再下一鏡對角雙區）。

scene 切換 = 構圖切換，絕不是風格切換。全片換風格是災難，全片一個構圖是催眠。與三方向門的銜接：使用者選定的方向板就是那張「定一次」的風格皮膚。

> 自檢：任取兩鏡對比，風格（色板 / 字型 / 材質）應該認不出差別，構圖應該一眼不同。反過來了就是架構錯了。

### 律十 · 禁區繼承（S10）

配相簿審美禁區全部繼承，且要特別警惕動畫的職業病：**發光粒子、資料流、全息 HUD、賽博霓虹是 motion graphics 最順手的偷懶素材，恰好全在花叔禁區**。做動畫時手比做靜態圖更癢，管住。

科技感的正解 = 真實 UI 截圖（3D 懸浮卡片形態）+ 乾淨大字 + 亮底。深藍底 #0D1117 + 霓虹 glow 這個組合照舊停用（細則同 SKILL.md §6.2）。

> 自檢：畫面裡有沒有任何元素在「發光」？有就先懷疑自己在用職業病偷懶，逐個論證去留。

### 律十一 · 3 米測試（S11）

任何一幀暫停，畫面裡最大的詞 3 米外可讀。**不因為「反正會動」而縮小字號**——觀眾看動畫時給每幀的注意力比看靜圖更少，字號只能更大不能更小。這條和 `animation-best-practices.md` §6.5 視覺密度條款互為上下限：密度條款防空曠，3 米測試防擁擠時犧牲可讀性。

> 自檢：把關鍵幀截圖縮到手機螢幕大小，最大的詞還能讀嗎？

## 3 · 景別體系：五檔 zoom 對映

傳統影視的遠全中近特五檔，在 HTML 動畫裡對應五個 zoom 檔位（檔位數值與 `camera-language.md` §4.3 一致，實作細節以它為準）：

| 景別 | zoom 檔位 | 看什麼 | 典型用途 | 出處 |
|---|---|---|---|---|
| 遠景 | 0.78x | 全域性 + 環境留白 | 開場 establishing、收尾全家福 | shotcraft 全頁機位 0.78 |
| 全景 | 1x（定場微推 1.06x） | 完整介面 / 完整場景 | 敘事基準面，多數鏡頭的家 | HuaRec 定場 1.06x 判例 |
| 中景 | 1.3-1.45x | 一個功能區塊 | 功能演示的主力景別 | HuaRec 輕推 / 中推檔 |
| 近景 | 1.8x | 單個元件 / 單條資料 | 強調具體互動 | HuaRec 重推檔 |
| 特寫 | 2.3x（上限） | 律二的具象錨點 | 關鍵數字、那個按鈕、logo | HuaRec 倍率上限 2.3x |

兩點說明：

- 同一個檔位可以用 zoom（scale，無視差）也可以用 dolly（perspective + translateZ，有視差）實作，氣質完全不同；兩者的選型規則和 camera rig 寫法在 `camera-language.md`，分鏡層只需要在 [CAMERA] 列寫清檔位和動機
- 檔位是設計詞彙不是枷鎖：1.5x、2.0x 都合法，檔位的作用是讓「中景」「特寫」這些詞在分鏡表裡有確定的數值含義

### 相鄰鏡頭的景別節奏

| 規則 | 內容 | 依據 |
|---|---|---|
| 避免同景別連切 | 相鄰兩鏡同檔位，切換沒有變化感，讀作「畫面跳了一下」而不是「換鏡頭了」；至少差一檔 | HuaRec「倍率 <1.25x 不值得拍」推廣到鏡間 |
| 避免兩級跳 | 遠景直切特寫（0.78x → 2.3x）會暈；要跳必須是有意為之的 punch-in，且配轉場（白閃 / whip-pan）墊住 | HuaRec 舒適預算 |
| 焦點近則並鏡 | 相鄰兩鏡焦點距離很近，合併成一鏡，聯合包圍盒重新定檔 | HuaRec 鏡間語法 |
| 焦點中距則平移 | 寧可用低一檔的景別一鏡平移過去，不做「拉出再推進」的泵動 | HuaRec「改平移」判例 |
| 焦點遠則棄鏡 | 對角橫跳的兩個焦點，絕不連拍兩個 zoom，砍掉一個或插全景過渡 | HuaRec「棄鏡」判例 |
| 時長隨幅度伸縮 | 景別切換的過渡時長不是常數：`duration = 0.55 × |ln(zoomTo/zoomFrom)| / ln2`，clamp [0.30, 0.94]s；固定 duration 是業餘感來源 | HuaRec 對數伸縮公式 |
| 節奏預算 | 相鄰鏡頭變化間隔 ≥2.6s，任意 15s 視窗內景別變化 ≤4-5 次 | HuaRec 舒適預算 A2 |
| 謝幕鐵律 | 成片永遠以全景 / 遠景收尾，結尾前 ≥0.8s 全景停頓；**絕不在推近態戛然而止** | HuaRec 謝幕判例 |

## 4 · 能量骨架：先撥出 hold 預算，再排動效

多鏡頭片子（≥10s）的鏡頭排列不是平均分配，套 shotcraft 的 promo-energy-arc 四段位骨架：

| 段位 | 時長佔比 | 能量 | 內容 | 硬指標 |
|---|---|---|---|---|
| ① 開場 | 8-12% | 低 | 品牌 / 主題亮相 | 字標落定 hold ≥1s |
| ② 單主角立傳 | 12-15% | 低中 · 全片最慢 | 主角一個完整動作弧（入場 → 懸停 → 落位） | 動作弧 ≥3s，質感最高的一段 |
| ③ 功能爬升 | 55-65% | 中高 ⇄ 低交替 | 每鏡綁一個獨特功能，能量高低交替排列 | 每 1-2 個功能鏡頭後插一張**呼吸字卡**（低能量、大留白、2-6 字） |
| ④ 收場 | 13-16% | 全片峰值 | 全家福 + sign-off | 收尾 hold，謝幕回全景（§3 鐵律） |

**排片紀律：先撥出 hold / rest 幀預算，再排動效**（shotcraft 填空流程判例）。具體順序：

1. 列功能清單，數出鏡頭數 N
2. 先把不可侵犯的靜止時間從總預算裡撥出：字標 hold ≥1s、批次動效收尾 0.5s 靜止、開場動作弧 ≥3s、結尾 ≥0.8s 全景停頓、關鍵結果前 0.5s 懸停（best-practices §4.4）
3. 剩下的時間才分給動效，能量高低交替排列，不許連續兩鏡高能
4. 逐接縫選轉場（§7），轉場幀從相鄰鏡頭的預算裡撥出，不另外加時

呼吸字卡的構圖也有定式：2-6 字大字 + 全螢幕負空間 + 零裝飾，它本身就是一張過封面測試的定格幀（活躍元素 = 1），作用是給功能爬升段降能量、給觀眾消化時間。別把呼吸字卡做成又一個資訊鏡頭，那等於沒插。

與 `animation-best-practices.md` §1 五段敘事的關係：Slow-Fast-Boom-Stop 是**單場 / 短片**（≤15s 一口氣）的節奏曲線，promo-energy-arc 是**多鏡頭片**的骨架；15s 以下二選一即可，20s 以上用能量骨架排鏡、每一鏡內部再用五段敘事的手感。

## 5 · 輕量分鏡卡：本檔案的交付物

每鏡一行，八個欄位一個不能少。shotcraft 的四列表（#|時間|鏡頭|關鍵動效）是最低配，這裡擴到八列，其中 [CAMERA] 獨立成列（launch film 導演稿的 10 欄位後續同步擴為 11，新增的就是這個欄位）：

```
| # | 時間 | 景別 | [CAMERA] 運鏡+動機 | 畫面構圖（百分比語言） | 關鍵動效 | 轉場到下一鏡 | 驗收幀號 |
```

欄位寫法要求：

- **時間**：起止秒 + 隱含時長；轉場時間含在本鏡預算內，不另列（§4 排片紀律第 4 條）
- **景別**：§3 五檔之一 + zoom 數值
- **[CAMERA]**：運鏡動作 + 一句動機；「靜止」也是合法運鏡，但要寫為什麼靜止；每個 push-in 必須寫錨點（律二）
- **畫面構圖**：百分比語言（律五），含前中後景分層（律六）
- **關鍵動效**：這一鏡只講一個動效（shotcraft「一鏡一動效」判例）
- **轉場到下一鏡**：§7 決策表選型，不許留空、不許寫「直接切」（裸切要寫成有意為之的 hidden-cut 才合法）
- **驗收幀號**：**每鏡預寫 1-2 個幀號**，實作完成後就截這幾幀自檢（shotcraft「每鏡三讀 + 預寫驗收幀號」判例）。預寫的意義：驗收標準在動手前就定死，不給實作後「看起來還行」的模糊空間

## 6 · Thumbnail Pass：動手寫正式程式碼前的灰盒驗證

分鏡表是文字，thumbnail pass 把它變成看得見的構圖驗證。成本半小時以內，重工成本的保險。

**Step 1 · 搭灰盒 HTML**：一個臨時 HTML，每個關鍵幀一個 1920×1080 的 `<section>`。只用純色塊 + 文字標籤擺構圖：主角一個深灰塊標「產品UI 85%」、文字區一個色塊標「大字：3000張截圖」、前景元素淺灰塊。不寫任何動效、不選字型、不調色，就是把分鏡卡的百分比語言變成可見的塊。

灰盒階段禁止調美（選字型、配色、加陰影都不許）：美是方向板已經定掉的事，灰盒只驗證構圖和節奏。開始調美 = 開始逃避構圖問題。

**Step 2 · 只做 3-5 張關鍵幀**：不是每鏡都做，挑能量骨架的關鍵節點：開場 setup 幀、立傳段 hero 幀、爬升段一張代表幀、峰值幀、謝幕幀。

**Step 3 · Playwright 批次截圖**：

```bash
for i in 1 2 3 4 5; do
  npx -y playwright screenshot "file://$PWD/thumbnails.html#f$i" \
    "thumbs/f$i.png" --viewport-size=1920,1080
done
```

**Step 4 · 驗收三問**（對著並排縮圖問）：

1. **蓋住所有文字標籤，5 張圖的構圖差異還看得出來嗎？** 看不出 = 節奏沒做出來，逐 scene 換構圖模板沒執行（律九；best-practices §1 的 thumbnail 自檢同源）
2. **每一張單獨過封面測試嗎？**（律一：1 主角 + ≤3 元素 + 1 焦點）
3. **每一張的引導線指得出來嗎？** 指不出來的那鏡回去修構圖，不要往下走（律三）

**Step 5 · 過了再寫正式程式碼**。灰盒 HTML 留在專案目錄裡當構圖基準，實作跑偏時回來對照。

**與三方向門的關係**：三方向硬門的「方向板」（hero 關鍵幀真實靜幀 + 色板 + 氣質句）本質就是**首版 thumbnail**。使用者選定方向後，thumbnail pass 是把那一張方向板擴充成整片的關鍵幀序列：方向板定風格皮膚，thumbnail pass 定逐鏡構圖，正好是律九的兩層正交。

## 7 · 轉場決策表：按敘事關係選型

轉場不是裝飾，是接縫處的敘事邏輯。先判斷相鄰兩鏡的**敘事關係**，再選型。轉場詞彙的實作參數（時長、easing、遮罩寫法）見 `camera-language.md` §7 的三層轉場詞彙。

| 相鄰兩鏡的敘事關係 | 首選轉場 | 備選 | 判例依據 |
|---|---|---|---|
| 時間跳躍（「三天後」「整理完成後」） | 黑場字卡 / 流白 | whip-pan | shotcraft 六式：大落差用白 / 黑墊 |
| 空間平移（同一介面的不同區域） | **一鏡平移，根本不切** | hidden-cut | HuaRec「中距離改平移」：寧可廣一檔一鏡過去，不做出-進泵動 |
| 概念對比（before/after、A vs B） | mask-wipe | 分割畫面後硬切 + 白閃 | shotcraft mask-wipe 穿窗判例 |
| 遞進 / 因果（setup 的答案在下一鏡） | 共享元素歸位（上一鏡元素飛成下一鏡主角） | morph | shotcraft travel 兩式；voiceover-pipeline「hero 跨 scene morph 不切」鐵律同源 |
| 能量落差大（呼吸字卡 → 高能鏡頭） | 流白 / 白閃 FlashCut | whip-pan | shotcraft：接縫按能量落差選型 |
| 能量落差小（爬升段相鄰功能鏡） | 虛焦接力 / 交叉淡化 ≥8f | hidden-cut | shotcraft graze-face-tour「段間交叉淡化防黑閃」 |

三條紀律：

1. **一個接縫只用一式**，不疊加（白閃 + whip-pan 一起上是 slop）
2. **轉場幀從相鄰鏡頭預算撥出**，不憑空加時長；分鏡表的時間列已含轉場
3. **全片零裸切**。shotcraft 判例原話：公認優秀的釋出片全程沒有一次裸切。要「切」的效果就用 hidden-cut（借滿版元素 / 白幀 / 運動峰值藏切點），那是設計過的切，不是沒設計的切

帶解說的片子多一條：**move on pause**（HuaRec 判例）。鏡頭切換和轉場吸附到語音間隙，只提前不推後，上限 0.8s，因為觀眾在聽覺空檔移動視線的認知成本最低。走 voiceover-pipeline 時用 timeline.json 的真實間隙定切點。

## 8 · 開工 checklist（分鏡完成的定義）

寫程式碼之前，確認以下全部存在：

- [ ] 分鏡表：每鏡一行、八欄位齊全，存進專案目錄（≥20s 時就是 `導演稿.md` 的核心節）
- [ ] 每鏡定格幀過了十一律裡適用的條目，至少顯式檢查律一（封面測試）、律三（引導線）、律五（百分比構圖）
- [ ] 景別列沒有同檔連切、沒有兩級跳（§3）
- [ ] hold / rest 預算先撥出了，呼吸字卡插了（§4）
- [ ] 每個接縫的轉場選型寫在表裡，全片零裸切（§7）
- [ ] thumbnail pass 的 3-5 張灰盒截圖過了驗收三問（§6）
- [ ] 每鏡預寫了驗收幀號，等實作後逐幀對照（§5）

七項全過，分鏡階段結束，進入實作。實作被退回時先分層定位：動效骨架的問題還是視覺工藝的問題（best-practices §6.5 的修復定式），分鏡表本身通常不用重寫。
